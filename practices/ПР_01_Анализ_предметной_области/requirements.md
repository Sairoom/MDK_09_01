# Требования к порталу Конференции РФ

Учебная информационная система объединяет каталог профессиональных событий, заявки участников и управление участием. Источник задания — практические работы МДК.09.01, портал «Конференции.РФ». Система хранит синтетические демонстрационные данные; приём денежных средств не реализуется и заданием не требуется.

## Пользователи и границы

Гость выбирает событие, регистрируется и входит в систему. Участник подаёт заявку на будущее событие, видит только свои заявки, отменяет новую заявку и оставляет один отзыв о завершённом мероприятии. Администратор просматривает все заявки, фильтрует их по статусу и переводит последовательно «Новая → Назначено → Завершено». Административная роль назначается только при начальном запуске из переменной ADMIN_PASSWORD; форма регистрации всегда создаёт участника.

Каталог событий заполняется начальной миграцией приложения. Редактирование каталога через административную форму, уведомления по почте, восстановление пароля и реальный платёжный шлюз не входят в объём этих практик.

## Функциональные требования

| Код | Требование | Проверка |
|---|---|---|
| F01 | Просмотр названия, даты UTC, места и описания события | Главная страница доступна гостю |
| F02 | Уникальные логин и email, пароль 8–128 символов, телефон +7 | Негативные и позитивные тесты регистрации |
| F03 | Вход и выход, защищённая сессия | Ротация CSRF, истечение сессии через 30 минут |
| F04 | Заявка с выбором мероприятия, помещения и способа оплаты | В БД появляется связанная запись |
| F05 | Запрет дубликата заявки и регистрации на прошедшее/заполненное событие | Сервер отклоняет повторную отправку |
| F06 | Просмотр только собственных заявок | Другой участник не получает чужие записи |
| F07 | Отмена только своей новой заявки | Назначенную и чужую заявку удалить нельзя |
| F08 | Просмотр и фильтр всех заявок администратором | Участнику доступ закрыт кодом 403 |
| F09 | Последовательная смена статусов | Пропуск и обратный переход отклоняются |
| F10 | Завершение только наступившего мероприятия | Будущую конференцию завершить нельзя |
| F11 | Один отзыв, 10–2000 символов, оценка 1–5 | Проверяются владелец, дата и статус |

Помещения: Большой зал, Мастерская, Онлайн. Способы оплаты: Банковская карта, Счёт для организации. Эти значения фиксированы и проверяются сервером по разрешённому списку.

## Нефункциональные требования

N01 — все страницы помещаются в ширину 390 px без горизонтальной прокрутки; базовый мобильный размер 390×844. N02 — подписи полей, навигация клавиатурой, видимый фокус, сообщения об ошибках в DOM, отключение анимации при prefers-reduced-motion. N03 — scrypt для паролей, параметры SQL, экранирование Jinja, CSRF для всех POST, HttpOnly и SameSite=Lax, права на сервере. Для HTTPS включается COOKIE_SECURE=1. N04 — список заявок получается одним JOIN-запросом, ограничен 200 строками, фильтр использует индекс; целевой отклик локальной главной страницы до 500 мс без холодного старта. N05 — миграции выполняются повторно без потери данных; внешние ключи и уникальность проверяются БД. N06 — приложение запускается по README, исходники разделены на шаблоны, сервисы и адаптер БД.

## Критерии приёмки

Проходят серверные сценарии tests/test_portal.py, браузерная проверка регистрации и заявки, отрицательные проверки прав и CSRF. Скриншоты отражают фактически запущенное приложение. Результаты измерений и ограничения среды приведены в docs/verification.md. Текущая учебная конфигурация имеет одного WSGI worker; ограничение попыток входа хранится в памяти процесса. Для нескольких worker нужен общий Redis либо эквивалентный limiter.
